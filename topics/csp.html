Constraint Satisfaction Problems (CSP)

Classes 11 & 12

What is Search For?

Assumptions about the world: a single agent, deterministic actions, fully observed state, discrete state space. Under those assumptions there are two very different jobs search can do:

PlanningIdentification
Sequences of actions. Assignments to variables.
The path to the goal is the important thing. The goal itself is important, not the path.
Paths have various costs and depths. All paths at the same depth (for some formulations).
Heuristics give problem-specific guidance. CSPs are specialized for identification problems.

What is a CSP?

In standard search problems, the state is a "black box" (an arbitrary data structure), the goal test can be any function, and so can the successor function. CSPs are a specialized subset of search problems for identification problems:

  • The state is defined by variables \( X_i \) with values from a domain \( D \) (sometimes \( D \) depends on \( i \)).
  • The goal test is a set of constraints specifying allowable combinations of values for subsets of variables.
  • Solutions are complete assignments satisfying all constraints.

A CSP is a simple example of a formal representation language, and it allows useful general-purpose algorithms with more power than standard search algorithms.

Example: Map Coloring

  • Variables: WA, NT, Q, NSW, V, SA, T (the regions of Australia).
  • Domains: \( D = \{ \text{red}, \text{green}, \text{blue} \} \)
  • Constraints: adjacent regions must have different colors.
    • Implicit: \( \text{WA} \neq \text{NT} \)
    • Explicit: \( (\text{WA}, \text{NT}) \in \{(\text{red},\text{green}), (\text{red},\text{blue}), \dots\} \)
  • Solutions are assignments satisfying all constraints, e.g. {WA = red, NT = green, Q = red, NSW = green, V = red, SA = blue, T = green}.

Example: N-Queens

Formulation 1 (Boolean): variables \( X_{ij} \) for each square, domains \( \{0, 1\} \), with constraints forbidding two queens in the same row, column or diagonal and requiring \( \sum_{i,j} X_{ij} = N \).

Formulation 2 (one variable per column):

  • Variables: \( Q_k \) — the row of the queen in column \( k \).
  • Domains: \( \{1, 2, \dots, N\} \)
  • Constraints:
    • Implicit: \( \forall i,j \) non-threatening \( (Q_i, Q_j) \) — i.e. \( Q_i \neq Q_j \) and \( |Q_i - Q_j| \neq |i - j| \).
    • Explicit: \( (Q_1, Q_2) \in \{(1,3), (1,4), \dots\} \)

Formulation 2 is far smaller — it builds the "one queen per column" constraint into the representation itself.

Example: Sudoku

  • Variables: each (open) square.
  • Domains: \( \{1, 2, \dots, 9\} \)
  • Constraints: 9-way alldiff for each column, each row, and each region (or a bunch of pairwise inequality constraints instead).

Varieties of CSPs

  • Discrete variables with finite domains: domain size \( d \) means \( O(d^n) \) complete assignments. E.g. Boolean CSPs, including Boolean satisfiability (NP-complete).
  • Discrete variables with infinite domains (integers, strings, etc.): e.g. job scheduling, where variables are start/end times for each job. Linear constraints are solvable; nonlinear constraints are undecidable.
  • Continuous variables: e.g. start/end times for Hubble Telescope observations. Linear constraints are solvable in polynomial time by linear programming methods.

Varieties of Constraints

  • Unary constraints: Involve a single variable (equivalent to reducing domains).
  • Binary constraints: Involve pairs of variables.
  • Higher-order constraints: Involve 3 or more variables (e.g., cryptarithmetic).
  • Preferences (soft constraints): Often representable by a cost for each variable assignment, leading to constrained optimization problems.

Constraint Graphs

A binary CSP is one in which each constraint relates at most two variables. It can be represented as a binary constraint graph, where nodes are variables and arcs show constraints.

General-purpose CSP algorithms use this graph structure to speed up search. In the Australia map-coloring problem, for example, Tasmania is an independent subproblem — it shares no constraint with any other region, so it can be solved separately.

Real-World CSPs

  • Assignment problems: e.g. who teaches what class.
  • Timetabling problems: e.g. which class is offered when and where?
  • Hardware configuration.
  • Transportation scheduling.
  • Factory scheduling.
  • Circuit layout.
  • Fault diagnosis.
  • … lots more! Note that many real-world problems involve real-valued variables.

Solving CSPs: Backtracking Search

The standard search formulation of CSPs uses partial assignments:

  • Initial state: The empty assignment, \( \{\} \).
  • Successor function: Assign a value to an unassigned variable.
  • Goal test: The current assignment is complete and satisfies all constraints.

We start with this straightforward, naïve approach, then improve it. What would BFS do here? What would DFS do? The problem with naïve search is that it explores an enormous number of assignments that differ only in the order the variables were assigned.

Backtracking search is the basic uninformed algorithm for solving CSPs. It is depth-first search with two improvements:

  1. One variable at a time: Variable assignments are commutative, so we can fix the ordering — [WA = red then NT = green] is the same as [NT = green then WA = red]. We only need to consider assignments to a single variable at each step.
  2. Check constraints as you go: Consider only values which do not conflict with previous assignments ("incremental goal test", or fail-on-violation). Note it might take some computation to check the constraints.

Backtracking = DFS + variable-ordering + fail-on-violation. Plain backtracking can solve n-queens for \( n \approx 25 \).

function BACKTRACKING-SEARCH(csp) returns a solution, or failure return RECURSIVE-BACKTRACKING({}, csp) function RECURSIVE-BACKTRACKING(assignment, csp) returns a solution, or failure if assignment is complete then return assignment var <- SELECT-UNASSIGNED-VARIABLE(VARIABLES[csp], assignment, csp) for each value in ORDER-DOMAIN-VALUES(var, assignment, csp) do if value is consistent with assignment given CONSTRAINTS[csp] then add {var = value} to assignment result <- RECURSIVE-BACKTRACKING(assignment, csp) if result != failure then return result remove {var = value} from assignment return failure

The two calls SELECT-UNASSIGNED-VARIABLE and ORDER-DOMAIN-VALUES are the choice points, and they are exactly what the improvements in the next section exploit.

Improving Backtracking

General-purpose ideas can give huge gains in speed for backtracking search. They answer three questions:

  • Ordering: Which variable should be assigned next? In what order should its values be tried?
  • Filtering: Can we detect inevitable failure early?
  • Structure: Can we exploit the problem structure?

1. Filtering: Detecting inevitable failure early

Filtering means keeping track of domains for unassigned variables and crossing off bad options as we go.

  • Forward checking: Cross off values that violate a constraint when added to the existing assignment. It propagates information from assigned to unassigned variables.
  • Constraint propagation: Forward checking doesn't provide early detection for all failures. For example, after assigning WA = red and Q = green, forward checking leaves NT and SA each with only {blue} — but NT and SA are adjacent, so they cannot both be blue. Forward checking never notices, because it only looks from assigned to unassigned variables. Constraint propagation reasons from constraint to constraint to find these tighter restrictions on variable domains.

2. Ordering: Which variable and which value?

  • Variable Ordering — Minimum Remaining Values (MRV): Choose the variable with the fewest legal values left in its domain. Also called the "most constrained variable" or "fail-fast" ordering. Why min rather than max? Because if a variable is going to fail, we want to discover it now rather than after assigning half the problem.
  • Value Ordering — Least Constraining Value: Given a choice of variable, choose the value that rules out the fewest values in the remaining variables. Note that it may take some computation to determine this (e.g. rerunning filtering). Why least rather than most? Because we only need one value to work for this variable, so we should keep as many options open downstream as possible.

Combining these ordering ideas makes 1000-queens feasible — up from \( n \approx 25 \) for plain backtracking.

3. Structure: Exploiting the constraint graph

The structure of the constraint graph itself can be exploited. Independent subproblems — connected components of the constraint graph, such as Tasmania in the map-coloring example — can be solved separately and their solutions combined, which turns one exponential problem into several much smaller ones.
