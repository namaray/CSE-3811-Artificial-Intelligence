First-Order Logic

Representing objects, properties and relationships — and reasoning from them with universal instantiation and modus ponens

What is First-Order Logic?

First-Order Logic (FOL), also called predicate logic, is a powerful knowledge representation tool in AI. It expands simple true/false statements into structured models of objects, properties and relationships, allowing machines to perform complex logical reasoning. It is commonly applied in NLP, expert systems and theorem proving.

Use of FOL in AI

FOL is useful for knowledge representation and reasoning. An AI system can use it to represent facts about a domain and infer conclusions from those facts. It has applications in expert systems, automated theorem proving, semantic reasoning, planning, and some forms of natural-language understanding.

In short: First-Order Logic gives AI a precise way to represent objects, properties, relationships and rules, so that the system can reason logically from known information.

Why not just true/false statements?

In plain true/false (propositional) logic, “Socrates is mortal” is a single symbol, say P, with no inside structure. There is no way to say “all humans are mortal” except by writing a separate symbol for every human. FOL breaks a statement into objects (Socrates) and properties (Human, Mortal), and adds variables and quantifiers, so one rule can cover every object at once:

∀x (Human(x) → Mortal(x))

Core Components

ComponentWhat it isExample
ConstantsSpecific, named objectsJohn, NewYork, Socrates
VariablesPlaceholders that can stand for any objectx, y
PredicatesProperties, traits or relations — they are either true or falseHuman(x), Brother(John, Bob)
FunctionsMap one object to another object — they return an object, not true/falseFatherOf(John)
QuantifiersSay how many objects a statement covers∀ “for all”, ∃ “there exists”
Logical connectivesJoin or modify statements∧ ∨ → ↔ ¬

Predicate vs function — a common mix-up. Father(Ali, Rahim) is a predicate: it is a statement, true or false (“Ali is the father of Rahim”). FatherOf(Rahim) is a function: it names a person (“Rahim's father”) and is not true or false by itself. You can put a function inside a predicate — Brother(John, FatherOf(Bob)) — but not the other way round.

Argument order matters

A predicate with two arguments has a fixed reading, and you must state it and stick to it. In the handout, Father(y, x) means “y is the father of x”, so Father(Ali, Rahim) means Ali is Rahim's father — not the reverse. When you introduce a predicate in an exam answer, write its meaning once, e.g. “Studies(x, y): x studies course y”.

The implication row to remember: P → Q is only false when P is true and Q is false. That is why, once we know a rule P → Q holds and P is true, Q must be true — the basis of every inference on this page.

The two patterns to remember

EnglishFOLConnective
All students are intelligent.∀x (Student(x) → Intelligent(x))∀ goes with →
Some student is intelligent.∃x (Student(x) ∧ Intelligent(x))∃ goes with ∧

Why not swap them? ∀x (Student(x) ∧ Intelligent(x)) says “everything is a student and intelligent” — far too strong. ∃x (Student(x) → Intelligent(x)) is true as soon as there is any non-student, because an implication with a false “if” part is true — far too weak.

Two quantifiers together — order matters

Problem 2 below uses ∀x [Student(x) → ∃y Studies(x, y)]: for every student there is some course they study — each student may study a different course. Swapping the order to ∃y ∀x would mean there is one single course that every student studies, which is a different claim.

“No …” statements

“No student is a professor” (Problem 5) can be written two equivalent ways:

∀x [Student(x) → ¬Professor(x)]    — every student is not a professor
¬∃x [Student(x) ∧ Professor(x)]    — there is no one who is both

The handout uses the first form; either is accepted.

Reasoning: Universal Instantiation + Modus Ponens

Almost every reasoning question in this course follows one pattern:

Rule:   ∀x (P(x) → Q(x))
Fact:   P(a)
Infer:  Q(a)

It is two steps glued together:

  1. Universal Instantiation (UI) — a rule that is true for all x is true for any particular object, so substitute it: from ∀x (P(x) → Q(x)) get P(a) → Q(a) by putting x = a.
  2. Modus Ponens (MP) — from P → Q and P, conclude Q.

How to write it in the exam — four labelled lines:

Rule∀x (Student(x) → Intelligent(x)) FactStudent(Ali) UI, x = AliStudent(Ali) → Intelligent(Ali) MP∴ Intelligent(Ali)

Watch out: modus ponens only works forwards. From ∀x (Human(x) → Mortal(x)) and Mortal(Tom) you cannot conclude Human(Tom) — Tom could be a mortal cat.

Worked Problems from the Handout

Problem 1 — Socrates

Fact: Socrates is a human. Rule: All humans are mortal.

FactHuman(Socrates) Rule∀x (Human(x) → Mortal(x)) UI, x = SocratesHuman(Socrates) → Mortal(Socrates) MP∴ Mortal(Socrates)

“Socrates is mortal.”

Problem 2 — Students and courses

Rahim is a student. Every student studies at least one course. Therefore, Rahim studies a course.

Predicates: Student(x): x is a student; Studies(x, y): x studies course y.

FactStudent(Rahim) Rule∀x [Student(x) → ∃y Studies(x, y)] UI, x = RahimStudent(Rahim) → ∃y Studies(Rahim, y) SinceStudent(Rahim) = True MP∴ ∃y Studies(Rahim, y)

Meaning: there exists at least one course that Rahim studies. Note the conclusion still has ∃y — we know such a course exists, but the knowledge base never says which one, so we cannot name it.

Problem 3 — Family relationship

Everyone's father is a parent. Ali is Rahim's father.

Predicates: Father(y, x): y is the father of x; Parent(y, x): y is a parent of x.

Rule∀x ∀y [Father(y, x) → Parent(y, x)] GivenFather(Ali, Rahim) UI, y = Ali, x = RahimFather(Ali, Rahim) → Parent(Ali, Rahim) MP∴ Parent(Ali, Rahim)

With two variables, instantiate both. Match by position: the first slot of Father(y, x) lines up with Ali, so y = Ali; the second with Rahim, so x = Rahim.

Problem 4 — Using AND (∧)

If a person is a student and studies AI, then the person is an AI student. Tanvir is a student and studies AI.

Rule∀x [(Student(x) ∧ Studies(x, AI)) → AIStudent(x)] GivenStudent(Tanvir),  Studies(Tanvir, AI) UI, x = Tanvir(Student(Tanvir) ∧ Studies(Tanvir, AI)) → AIStudent(Tanvir) SinceStudent(Tanvir) ∧ Studies(Tanvir, AI) = True MP∴ AIStudent(Tanvir)

With ∧ in the “if” part, you must show every condition is true before firing the rule. Here AI is a constant (the course), not a variable.

Problem 5 — Using NOT (¬)

No student is a professor. Rahim is a student.

Rule∀x [Student(x) → ¬Professor(x)] GivenStudent(Rahim) UI, x = RahimStudent(Rahim) → ¬Professor(Rahim) MP∴ ¬Professor(Rahim)

The AI can conclude that Rahim is not a professor. A negated conclusion is still an ordinary modus ponens step.

Problem 6 — A typical AI reasoning problem

Knowledge base:

Human(Ali)
Human(Rahim)
∀x [Human(x) → Mortal(x)]

Question: Is Ali mortal?

UI, x = AliHuman(Ali) → Mortal(Ali) SinceHuman(Ali) = True MP∴ Mortal(Ali)

Yes, Ali is mortal. The same rule can be instantiated again for another object — similarly, x = Rahim gives Mortal(Rahim). One universal rule, used as many times as needed.

Applications

  • Knowledge representation: represents objects, properties and relationships in a structured form for reasoning tasks.
  • Automated theorem proving: applies logical rules to prove mathematical statements and verify system correctness.
  • Natural language processing (NLP): helps convert natural language into logical representations for understanding and reasoning.
  • Expert systems: encode domain knowledge to support decision-making, e.g. medical or legal assistants.
  • Semantic web: defines relationships between web resources for better search and information retrieval.

Practice Questions

Try each one on paper first, then open the answer.

1. Translate into FOL: (a) All birds can fly. (b) Some students like AI. (c) No cat is a dog. (d) Every person has a mother. (e) Karim is a teacher and teaches AI.

Answer
(a)∀x (Bird(x) → CanFly(x)) (b)∃x (Student(x) ∧ Likes(x, AI)) (c)∀x (Cat(x) → ¬Dog(x)) (d)∀x (Person(x) → ∃y Mother(y, x)) (e)Teacher(Karim) ∧ Teaches(Karim, AI)

In (d), Mother(y, x) means y is the mother of x. (b) uses ∧ because it starts with ∃; (e) has no quantifier because it is about one named person.

2. In Brother(John, FatherOf(Bob)), identify every constant, predicate and function, and say what the sentence means.

Answer
  • Constants: John, Bob
  • Predicate: Brother — true or false
  • Function: FatherOf — returns an object (Bob's father)

Meaning: “John is the brother of Bob's father” — i.e. John is Bob's uncle.

3. Knowledge base: if a student passes AI, the student graduates. Nadia is a student. Nadia passes AI. Write the KB in FOL and prove that Nadia graduates.

Answer
Rule∀x [(Student(x) ∧ Passes(x, AI)) → Graduates(x)] FactsStudent(Nadia),  Passes(Nadia, AI) UI, x = Nadia(Student(Nadia) ∧ Passes(Nadia, AI)) → Graduates(Nadia) SinceStudent(Nadia) ∧ Passes(Nadia, AI) = True MP∴ Graduates(Nadia)

4. Knowledge base: ∀x (Bird(x) → HasWings(x)), ∀x (HasWings(x) → CanFly(x)), Bird(Tweety). Prove CanFly(Tweety).

Answer

Apply the pattern twice — the conclusion of the first step is the fact for the second.

UI, x = TweetyBird(Tweety) → HasWings(Tweety) MPHasWings(Tweety) UI, x = TweetyHasWings(Tweety) → CanFly(Tweety) MP∴ CanFly(Tweety)

5. Knowledge base: ∀x (Human(x) → Mortal(x)) and Mortal(Tom). Can the AI conclude Human(Tom)? Explain.

Answer

No. The rule only says humans are mortal; it does not say that only humans are mortal. Modus ponens needs the “if” part (Human(Tom)) to be known, and here we only know the “then” part. Reasoning backwards like this is a fallacy (affirming the consequent) — Tom could be a mortal animal.

6. Explain the difference between ∀x ∃y Loves(x, y) and ∃y ∀x Loves(x, y).

Answer
  • ∀x ∃y Loves(x, y): everyone loves somebody — each person may love a different person.
  • ∃y ∀x Loves(x, y): there is one particular person whom everyone loves.

The second is a much stronger claim. Changing the order of different quantifiers changes the meaning.

Exam Checklist

  • Define FOL: predicate logic — a knowledge representation tool for objects, properties, relationships and rules that lets AI reason from known facts.
  • Name the six core components — constants, variables, predicates, functions, quantifiers, connectives — with an example of each.
  • Know that a predicate is true/false while a function returns an object.
  • ∀ goes with →; ∃ goes with ∧; “no P is Q” is ∀x (P(x) → ¬Q(x)).
  • State what each predicate's arguments mean, especially the order in two-argument predicates.
  • For inference, write Rule → Fact → UI (x = a) → MP → ∴ conclusion, one line each.
  • With ∧ in the “if” part, show every condition is true before concluding.
  • Modus ponens only goes forwards: knowing Q does not give you P.
  • List the applications: knowledge representation, theorem proving, NLP, expert systems, semantic web.
