How to Read It

  • Triangles pointing up (▲) are MAX nodes — they take the largest value among their children. Triangles pointing down (▼) are MIN nodes — they take the smallest. Squares at the bottom are terminal states, labelled with their utility.
  • Minimax is a depth-first exploration: it dives all the way to the leftmost leaf before it can assign a value to anything. Watch the white outline travel down and to the left first.
  • A node's value only becomes final when the algorithm returns from it — the running value \( v \) you see updating is a partial best-so-far.

Switch to Alpha-Beta to see the difference

In alpha-beta mode each node also displays its \( \alpha \) and \( \beta \) bounds:

  • \( \alpha \) = the best value MAX can already guarantee along this path.
  • \( \beta \) = the best value MIN can already guarantee along this path.
  • At a MAX node, as soon as \( v \geq \beta \), the remaining children are pruned — MIN would never let the game reach here, so their values cannot change the root's decision.
  • At a MIN node, the mirror condition is \( v \leq \alpha \).

Run both algorithms on the same tree and compare "Nodes visited". The root value is always identical — pruning never changes the answer, only the amount of work. That is the whole point of the algorithm.

Note also that pruning depends on move ordering: randomize the leaves a few times in alpha-beta mode and watch the visited-node count swing between the worst case \( O(b^m) \) and the best case \( O(b^{m/2}) \).
