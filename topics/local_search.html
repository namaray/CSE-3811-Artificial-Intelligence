Local Search Algorithms and Optimization

Classes 7 & 8

Classical Search vs. Local Search

Classical Search

Designed to explore search spaces systematically by keeping one or more paths in memory and recording which alternatives have been explored. Suitable for observable, deterministic, known environments where the solution is a sequence of actions.

Local Search

Evaluates and modifies one or more current states rather than systematically exploring paths from an initial state. It operates using a single current node and generally moves only to neighbors of that node. Paths are not retained.

  • Advantages: Uses very little memory (constant amount); can find reasonable solutions in large or infinite (continuous) state spaces.
  • Suitable for: Pure optimization problems where the aim is to find the best state according to an objective function, and the path to the goal does not matter (e.g., 8 Queens problem).

Local search is not systematic, but it suits problems in which all that matters is the solution state, not the path cost to reach it — for example the 8-queens problem. In pure optimization problems, nature itself provides the objective function: Darwinian evolution can be seen as attempting to optimize reproductive fitness, but there is no "goal test" and no "path cost" for that problem.

State-space Landscape

A landscape where location is defined by the state and elevation is defined by the heuristic cost function or objective function.

  • If elevation corresponds to cost, the aim is to find the lowest valley (global minimum).
  • If elevation corresponds to an objective function, the aim is to find the highest peak (global maximum).
  • You can convert from one to the other just by inserting a minus sign.

A complete local search algorithm always finds a goal if one exists. An optimal algorithm always finds a global minimum/maximum.

The Local Search Algorithms

  • Hill-climbing
  • Simulated annealing (inspired by statistical physics)
  • Beam search
  • Genetic algorithms (inspired by evolutionary biology)

Local Search Algorithms

1. Hill-climbing Search (Steepest-ascent version)

A loop that continually moves in the direction of increasing value (uphill). It terminates when it reaches a peak where no neighbor has a higher value. It does not maintain a search tree, so the data structure for the current node need only record the state and the value of the objective function.

function HILL-CLIMBING(problem) returns a state that is a local maximum current <- MAKE-NODE(problem.INITIAL-STATE) loop do neighbor <- a highest-valued successor of current if neighbor.VALUE <= current.VALUE then return current.STATE current <- neighbor

Hill-climbing does not look ahead beyond the immediate neighbors of the current state. This resembles trying to find the top of Mount Everest in a thick fog while suffering from amnesia. It is sometimes called greedy local search, because it grabs a good neighbor state without thinking ahead about where to go next.

Example: the 8-queens problem

  • Typically uses a complete-state formulation, where each state has 8 queens on the board, one per column.
  • The successors of a state are all possible states generated by moving a single queen to another square in the same column — each state has \( 8 \times 7 = 56 \) successors.
  • The heuristic cost function \( h \) is the number of pairs of queens attacking each other, either directly or indirectly.
  • The global minimum of this function is zero, which occurs only at perfect solutions.

Why hill-climbing gets stuck

In each of these cases the algorithm reaches a point at which no progress is being made:

  • Local maxima: A peak higher than each of its neighboring states but lower than the global maximum. Algorithms that reach the vicinity of a local maximum are drawn upward toward the peak but then get stuck with nowhere else to go.
  • Ridges: A ridge is a chain of hills forming a continuous elevated crest, with sides sloping away from a narrow top. Ridges result in a sequence of local maxima that is very difficult for greedy algorithms to navigate.
  • Plateaux: A flat area of the state-space landscape. It can be a flat local maximum (from which no uphill exit exists) or a shoulder (from which progress is possible).

How well does it actually do?

Starting from a randomly generated 8-queens state, steepest-ascent hill climbing gets stuck 86% of the time, solving only 14% of problem instances. It works quickly, taking just 4 steps on average when it succeeds and 3 when it gets stuck — not bad for a state space with \( 8^8 \approx 17 \) million states.

Allowing sideways moves. Hill-climbing halts if it reaches a plateau where the best successor has the same value as the current state. What if we allow sideways moves, hoping the plateau is really a shoulder? Good, but be cautious: if we always allow sideways moves when there are no uphill moves, an infinite loop occurs whenever the algorithm reaches a flat local maximum that is not a shoulder. One common solution is to put a limit on the number of consecutive sideways moves allowed.

  • Allowing 100 consecutive sideways moves in 8-queens raises the success rate from 14% to 94%.
  • Success comes at a cost: the algorithm then averages roughly 21 steps for each successful instance and 64 for each failure.

Variants of Hill-climbing

VariantHow it picks a moveComplete?
Steepest-ascent Always takes the best uphill neighbor. Incomplete
Stochastic hill climbing Chooses at random from among the uphill moves; the probability of selection can vary with steepness. Usually converges more slowly than steepest ascent, but in some landscapes finds better solutions. Incomplete
First-choice hill climbing Implements stochastic hill climbing by generating successors randomly until one is better than the current state. A good strategy when a state has many (e.g. thousands of) successors. Incomplete
Random-restart hill climbing Conducts a series of hill-climbing searches from randomly generated initial states, until a goal is found. Trivially complete

The success of hill climbing depends very much on the shape of the state-space landscape. If there are few local maxima and plateaux, random-restart hill climbing finds a good solution very quickly. However, many real problems have many local maxima, ridges and plateaux, and NP-hard problems typically have an exponential number of local maxima to get stuck on. Despite this, a reasonably good local maximum can often be found after a small number of restarts.

2. Simulated Annealing

A hill-climbing algorithm that never makes "downhill" moves is guaranteed to be incomplete, because it can get stuck on a local maximum. In contrast, a purely random walk — moving to a successor chosen uniformly at random — is complete but extremely inefficient. Simulated annealing combines the two to yield both efficiency and completeness.

Intuition: imagine getting a ping-pong ball into the deepest crevice in a bumpy surface. If we just let the ball roll, it comes to rest at a local minimum. If we shake the surface, we can bounce the ball out of that local minimum. The trick is to shake just hard enough to escape local minima but not hard enough to dislodge the ball from the global minimum. The simulated-annealing solution is to start by shaking hard (a high temperature) and then gradually reduce the intensity of the shaking (lower the temperature).

  • Instead of picking the best move, it picks a random move.
  • If the move improves the situation, it is always accepted.
  • Otherwise, it accepts the move with a probability less than 1: \( P = e^{\Delta E / T} \)
  • The probability decreases exponentially with the "badness" of the move (\( \Delta E \)) and also decreases as the "temperature" \( T \) goes down.
  • If the schedule lowers \( T \) slowly enough, it will find a global optimum with probability approaching 1.
function SIMULATED-ANNEALING(problem, schedule) returns a solution state current <- MAKE-NODE(problem.INITIAL-STATE) for t = 1 to ∞ do T <- schedule(t) if T = 0 then return current next <- a randomly selected successor of current ΔE <- next.VALUE - current.VALUE if ΔE > 0 then current <- next else current <- next only with probability e^(ΔE/T)

Applications: simulated annealing was first used extensively to solve VLSI layout problems in the early 1980s. It has since been applied widely to factory scheduling and other large-scale optimization tasks.

3. Beam Search

Local beam search keeps track of \( k \) states rather than just one. It begins with \( k \) randomly generated states.

  • At each step, all successors of all \( k \) states are generated.
  • If any one is a goal, it halts. Otherwise, it selects the \( k \) best successors from the complete list and repeats.
  • Useful information is passed among the parallel \( k \) search threads: the algorithm quickly abandons unfruitful searches and moves its resources to where the most progress is being made. This is not the same as random-restart with \( k \) restarts, where the runs are independent.
  • Drawback: it can suffer from a lack of diversity among the \( k \) states, which can quickly become concentrated in a small region of the state space — making the search little more than an expensive version of hill climbing.
  • Stochastic beam search: Instead of choosing the best \( k \), it chooses \( k \) successors at random, with the probability of choosing a successor being an increasing function of its value. This resembles natural selection, where the offspring of an organism populate the next generation according to its fitness.

4. Genetic Algorithms (GA)

A variant of stochastic beam search in which successor states are generated by combining two parent states (crossover) rather than modifying a single state.

  • Begins with a set of \( k \) randomly generated states called the population.
  • Each state (individual) is represented as a string over a finite alphabet.
  • Each state is rated by the objective function called the fitness function, which should return higher values for better states. For the 8-queens problem we use the number of nonattacking pairs of queens, which has a value of 28 for a solution.
  • Pairs are selected randomly for reproduction, with the probability of being chosen directly proportional to the fitness score. Note that one individual may be selected twice and another not at all. There are many variants of this selection rule — the method of culling, in which all individuals below a given threshold are discarded, can be shown to converge faster than the random version.
  • For each pair to be mated, a crossover point is chosen randomly from the positions in the string, and offspring are created by crossing over the parent strings at that point. Encoding matters here: if a 24-bit encoding is used instead of 8 digits, the crossover point has a 2/3 chance of landing in the middle of a digit, which results in an essentially arbitrary mutation of that digit.
  • Each location is subject to random mutation with a small independent probability. In the 8-queens problem, this corresponds to choosing a queen at random and moving it to a random square in its column.

The population is often quite diverse early on, so crossover (like simulated annealing) frequently takes large steps in the state space early in the search and smaller steps later, when most individuals are quite similar.

Where the advantage comes from

Like stochastic beam search, genetic algorithms combine an uphill tendency with random exploration and exchange of information among parallel search threads. The primary advantage, if any, comes from the crossover operation — yet it can be shown mathematically that if the positions of the genetic code are permuted initially in a random order, crossover conveys no advantage.

Intuitively, the advantage comes from crossover's ability to combine large blocks of letters that have evolved independently to perform useful functions, raising the level of granularity at which the search operates. For example, putting the first three queens in positions 2, 4 and 6 (where they do not attack each other) may constitute a useful block that can be combined with other blocks to construct a solution.

The theory explains this using the idea of a schema — a substring in which some positions are left unspecified. For example the schema 246***** describes all 8-queens states in which the first three queens are in positions 2, 4 and 6; strings matching it (such as 24613578) are called instances of the schema. If the average fitness of the instances of a schema is above the mean, the number of instances within the population will grow over time. This effect is unlikely to be significant if adjacent bits are totally unrelated to each other, because then there will be few contiguous blocks that provide a consistent benefit.

Genetic algorithms work best when schemata correspond to meaningful components of a solution. If the string represents an antenna, the schemata may represent components such as reflectors and deflectors — a good component is likely to be good in a variety of designs. Successful use of genetic algorithms therefore requires careful engineering of the representation.

Genetic algorithms have had a widespread impact on optimization problems such as circuit layout and job-shop scheduling. At present it is not clear whether their appeal arises from their performance or from their æsthetically pleasing origins in the theory of evolution; much work remains to identify the conditions under which they perform well.
