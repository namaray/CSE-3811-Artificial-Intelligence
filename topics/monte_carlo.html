Monte Carlo Methods

Estimating by repeated random sampling — from expected values and π to action values and a clinic simulation

What is a Monte Carlo Algorithm?

A Monte Carlo algorithm is a computational process that uses random numbers to produce an outcome. It simulates the behaviour of other systems. It is not an exact method but a heuristic one: it uses randomness and statistics to get a result.

  • Monte Carlo methods use repeated random sampling to solve complex problems involving uncertainty, probability and optimization in AI.
  • Monte Carlo simulation is a method used to predict and understand the behaviour of systems involving uncertainty.
  • They solve difficult AI problems by repeatedly using random simulations to estimate the probability or expected quality of different outcomes.

How does Monte Carlo simulation work?

  1. Define the problem — identify the process to simulate, e.g. stock prices or an engineering model.
  2. Model the inputs — e.g. use a normal distribution to represent stock-price fluctuations.
  3. Run simulations — generate random inputs from the chosen distributions and repeat the process many times.
  4. Analyse the results — the output is a distribution of outcomes: a range of possible scenarios, not just a single expected value.

The core formula

Given a function \(f(x)\) and a domain \(D\), the expected value of \(f\) is estimated by averaging it over random samples:

\[ E[f(x)] \approx \frac{1}{N} \sum_{i=1}^{N} f(x_i) \]

where \(N\) is the number of random samples and the \(x_i\) are random samples drawn from \(D\). Everything else on this page is this one formula applied to different things.

Applications in AI

  • Game playing — chess, Go, poker.
  • Reinforcement learning — estimating returns and action values.
  • Probabilistic inference — estimating probabilities in complex models.
  • Robotics — planning under uncertainty.
  • Optimization — finding good solutions in large search spaces.
  • Decision-making — evaluating uncertain outcomes.

Example. If a move is simulated 1,000 times and wins 650 times, its estimated winning probability is \(P(\text{win}) = 650/1000 = 0.65\), i.e. 65%.

The Basic Mathematical Idea

Estimating an expected value

Suppose we want the expected value of a random variable \(X\):

\[ \mu = E[X] = \int x\,f(x)\,dx \]

where \(f(x)\) is the probability density function. If this integral is hard to compute analytically, estimate it with random samples: draw \(N\) independent samples \(X_1, X_2, \dots, X_N\) from the distribution of \(X\), and take their mean:

\[ \hat{\mu} = \frac{1}{N} \sum_{i=1}^{N} X_i \]

Example. Take these \(N = 5\) samples:

\[ X_1 = 2,\quad X_2 = 5,\quad X_3 = 3,\quad X_4 = 7,\quad X_5 = 4 \]

Their mean is the estimate:

\[ \hat{\mu} = \frac{2+5+3+7+4}{5} = \frac{21}{5} = 4.2 \qquad\Rightarrow\qquad E[X] \approx 4.2 \]

Estimating a probability

To estimate \(P(A)\), run \(N\) random trials and define an indicator variable for each:

\[ I_i = \begin{cases} 1, & \text{if event } A \text{ occurs} \\ 0, & \text{otherwise} \end{cases} \]

Then \(P(A) = E[I]\), so a probability is just the expected value of an indicator, and the same averaging works:

\[ \hat{P}(A) = \frac{1}{N} \sum_{i=1}^{N} I_i \]

Example. In 10 simulations, event A occurs 6 times, so \(I_1 + I_2 + \cdots + I_{10} = 6\) and \(\hat{P}(A) = 6/10 = 0.6\), i.e. 60%.

Why does Monte Carlo work?

The mathematical foundation is the Law of Large Numbers: as the number of samples grows, the sample mean converges to the true mean.

\[ \frac{1}{N} \sum_{i=1}^{N} X_i \;\rightarrow\; E[X] \quad\text{as } N \rightarrow \infty, \qquad\text{so}\qquad \hat{\mu} \rightarrow \mu \]

More simulations generally produce a more accurate estimate.

Monte Carlo error

The standard error of a Monte Carlo estimate is approximately

\[ SE = \frac{\sigma}{\sqrt{N}} \qquad\Rightarrow\qquad \text{Error} \propto \frac{1}{\sqrt{N}} \]

where \(\sigma\) is the standard deviation of the population and \(N\) the number of simulations.

The key consequence: increasing the number of simulations by 100× reduces the typical error by only 10×. Accuracy is cheap at first and expensive later — each extra decimal place of precision costs 100 times more simulation.

A Classic Example: Estimating π

Take the unit square \(0 \le x \le 1,\ 0 \le y \le 1\), and the quarter circle inside it, \(x^2 + y^2 \le 1\).

\[ A_s = 1 \times 1 = 1 \qquad\qquad A_c = \frac{\pi r^2}{4} = \frac{\pi (1)^2}{4} = \frac{\pi}{4} \] \[ \frac{A_c}{A_s} = \frac{\pi / 4}{1} = \frac{\pi}{4} \qquad\Rightarrow\qquad \pi = 4\,\frac{A_c}{A_s} \]

This is why the 1×1 square is convenient: its area is 1, so the area ratio is the quarter circle's area.

Generate and count random points

Generate \(N\) random points \((x_i, y_i)\), with \(x_i, y_i \sim U(0, 1)\). For every point check whether \(x_i^2 + y_i^2 \le 1\); if so it lies inside the quarter circle. Count those as \(N_c\). The fraction landing inside estimates the area ratio:

\[ \frac{N_c}{N} \approx \frac{\text{Area of quarter circle}}{\text{Area of square}} = \frac{\pi}{4} \qquad\Rightarrow\qquad \hat{\pi} = 4\,\frac{N_c}{N} \]

Worked examples

\(N\)\(N_c\)\(N_c / N\)\(\hat{\pi} = 4 N_c / N\)

The first is close to \(\pi = 3.14159\ldots\), since \(\pi/4 \approx 0.785\) — about 78.54% of points should land inside. The second is far off: only 70% landed inside. With more random points, the estimate tends to approach π.

Worth noticing — use the error formula on the second example. For a proportion, \(\sigma = \sqrt{p(1-p)}\), so with \(N = 10{,}000\):

\[ SE\!\left(\tfrac{N_c}{N}\right) = \sqrt{\frac{0.785 \times 0.215}{10000}} \approx 0.0041 \qquad\Rightarrow\qquad SE(\hat{\pi}) \approx 4 \times 0.0041 \approx 0.016 \]

So a genuine run of 10,000 points should land within about ±0.03 of π roughly 95% of the time. Getting 2.8 is about 20 standard errors away — not bad luck but a sign of a broken random number generator. Treat that example as illustrating the arithmetic, not as a realistic outcome at this \(N\).

Monte Carlo in AI

In AI, the same principle estimates the value of an action. Suppose an agent has an action \(a\), and we run \(N\) simulations with rewards \(R_1, R_2, \dots, R_N\). The estimated value of \(a\) is their mean:

\[ \hat{Q}(a) = \frac{1}{N} \sum_{i=1}^{N} R_i \]

Example. Five simulations give \(R = 10, 5, 8, 12, 15\):

\[ \hat{Q}(a) = \frac{10+5+8+12+15}{5} = \frac{50}{5} = 10 \]

If another action has \(\hat{Q}(b) = 7\), the AI prefers \(a\), because \(\hat{Q}(a) > \hat{Q}(b)\).

Monte Carlo Tree Search (MCTS)

For MCTS, the mathematical process is:

Random simulations  →  Rewards  →  Average reward  →  Action selection

For a node (state) \(s\) and action \(a\):

\[ Q(s, a) = \frac{W(s, a)}{N(s, a)} \]
  • \(N(s, a)\) — number of times action \(a\) was simulated from state \(s\)
  • \(W(s, a)\) — total accumulated reward
  • \(Q(s, a)\) — estimated average value

Example. An action simulated 100 times accumulating a total reward of 65 has \(N(s,a) = 100\), \(W(s,a) = 65\), so \(Q(s, a) = 65/100 = 0.65\).

This is the core idea behind Monte Carlo methods in AI: use repeated random simulations and their average outcome to estimate an unknown probability, value, or decision quality.

Worked example: choosing between two actions

Run 5 independent simulations of each action from state \(s\):

ActionReturns \(G_1 \dots G_5\)Sum\(\hat{Q}(s, \cdot) = \text{sum} / 5\)
\(a\)8, 6, 10, 7, 9408
\(b\)5, 8, 6, 7, 4306

Since \(\hat{Q}(s, a) = 8 > \hat{Q}(s, b) = 6\), the AI selects action \(a\).

General Monte Carlo formula in AI

\[ \hat{Q}(s, a) = \frac{G_1 + G_2 + \cdots + G_N}{N} \qquad\text{and as } N \rightarrow \infty,\quad \hat{Q}(s, a) \rightarrow Q(s, a) \]

This is the mathematical foundation of Monte Carlo methods in reinforcement learning and MCTS.

Key point: Monte Carlo does not calculate \(Q(s, a)\) exactly. It estimates \(Q(s,a)\) by repeatedly simulating possible outcomes and averaging their returns. With only five runs per action, as here, the estimates are rough — the error formula above says the comparison becomes trustworthy only as \(N\) grows.

Why the waits keep growing. The expected service time is

This sample was worse than average: its mean service time was 45 minutes, which is why the last patient waits 105 minutes and the clinic runs until 2:00 instead of noon.

One run of 8 patients is a single random sample. A proper Monte Carlo study would repeat the day with many sets of random numbers and average the results — exactly the \(1/\sqrt{N}\) story above.

Exam Checklist

  • Define Monte Carlo: repeated random sampling to estimate quantities — heuristic, not exact.
  • Estimate an expected value as a sample mean, and a probability as the mean of an indicator.
  • Cite the Law of Large Numbers for why it works, and \(SE = \sigma/\sqrt{N}\) for how accurate it is.
  • Derive \(\hat{\pi} = 4N_c/N\) from the area ratio of the quarter circle to the unit square.
  • Compute \(\hat{Q}(s,a)\) as an average of returns, or \(W/N\), and pick the action with the larger estimate.
  • For a simulation problem: cumulative probabilities → random-number intervals → category per random number → event table → averages.
  • In a queue table, service starts at max(arrival, doctor free).
