Informed Search Strategies & Heuristic Functions

Classes 4–6  •  AIMA 3.4, 3.5, 3.6

Recap: Search

  • Search problem: states (configurations of the world), actions and costs, a successor function (world dynamics), a start state and goal test.
  • Search tree: nodes represent plans for reaching states; plans have costs (sum of action costs).
  • Search algorithm: systematically builds a search tree, chooses an ordering of the fringe (unexplored nodes). It is optimal if it finds least-cost plans.

Uniform Cost Search is complete and optimal, but it explores options in every "direction" because it has no information about the goal location. Informed search fixes that by adding a heuristic.

Search Heuristics

A heuristic is a function that estimates how close a state is to a goal. It is designed for a particular search problem.

Examples: Manhattan distance or Euclidean distance for pathing problems; straight-line distance to Bucharest for the Romania problem.

Greedy Search

Strategy: Expand the node that you think is closest to a goal state — order the fringe by \( h(n) \) alone.

  • A common case: "best-first" takes you straight to the (wrong) goal.
  • Worst case: like a badly-guided DFS.

A* Search

A* Search combines the benefits of Uniform Cost Search (UCS) and Greedy Search.

  • UCS orders by path cost, or backward cost \( g(n) \).
  • Greedy orders by goal proximity, or forward cost \( h(n) \).
  • A* Search orders by the sum:
\[ f(n) = g(n) + h(n) \]

When should A* terminate?

We should only stop when we dequeue a goal, not when we enqueue a goal. Enqueueing a goal proves only that some path to the goal exists — a cheaper one may still be sitting in the fringe.

Is A* Optimal?

Not automatically. If the estimated cost of a good goal exceeds the actual cost of a bad goal, A* can return a suboptimal path. We need estimates to be less than or equal to actual costs — which is exactly the admissibility condition below.

  • A* is optimal for tree search if the heuristic is admissible.
  • A* is optimal for graph search if the heuristic is consistent.

Admissibility and Consistency

Admissible Heuristics

A heuristic \( h \) is admissible (optimistic) if:

\[ 0 \leq h(n) \leq h^*(n) \]

where \( h^*(n) \) is the true cost to a nearest goal. Inadmissible (pessimistic) heuristics break optimality by trapping good plans on the fringe. Admissible heuristics slow down bad plans but never outweigh true costs.

Coming up with admissible heuristics is most of what's involved in using A* in practice.

Creating Admissible Heuristics

Most of the work in solving hard search problems optimally is in coming up with admissible heuristics. Often, admissible heuristics are solutions to relaxed problems, where new actions are available. Inadmissible heuristics are often useful too.

Consistency of Heuristics

Main idea: estimated heuristic costs \( \leq \) actual costs.

  • Admissibility: heuristic cost \( \leq \) actual cost to goal — \( h(A) \leq \) actual cost from A to G.
  • Consistency: heuristic "arc" cost \( \leq \) actual cost for each arc.
\[ h(A) - h(C) \leq \text{cost}(A \rightarrow C) \]

Consequences of consistency:

  • The \( f \) value along a path never decreases: \( h(A) \leq \text{cost}(A \rightarrow C) + h(C) \)
  • A* graph search is optimal.
  • Consistency implies admissibility.

Example: The 8 Puzzle

The 8 puzzle is the standard worked example for heuristic design. Ask first: what are the states, how many states are there, what are the actions, how many successors from the start state, and what should the costs be?

8 Puzzle I — Number of tiles misplaced

  • Heuristic: the number of tiles that are not in their goal position.
  • Why is it admissible? Every misplaced tile needs at least one move, so the count can never exceed the true cost.
  • \( h(\text{start}) = 8 \)
  • This is a relaxed-problem heuristic: it solves the puzzle where a tile may be teleported to its goal square in one move.

8 Puzzle II — Total Manhattan distance

What if we had an easier 8-puzzle where any tile could slide any direction at any time, ignoring other tiles? The solution cost of that relaxed problem is the total Manhattan distance.

  • Why is it admissible? Each tile must travel at least its Manhattan distance, and moves shift one tile at a time.
  • \( h(\text{start}) = 3 + 1 + 2 + \dots = 18 \)

8 Puzzle III — Why not use the actual cost?

The exact cost \( h^* \) would be admissible and would expand almost no nodes — but computing it is as hard as solving the puzzle itself.

With A* there is a trade-off between quality of the estimate and work per node. As heuristics get closer to the true cost you expand fewer nodes, but usually do more work per node to compute the heuristic itself.

Trivial Heuristics & Dominance

Dominance: \( h_a \geq h_c \) if \( \forall n:\ h_a(n) \geq h_c(n) \). A dominant admissible heuristic is always at least as good — it never expands more nodes.

Heuristics form a semi-lattice:

  • The max of admissible heuristics is admissible: \( h(n) = \max(h_a(n), h_b(n)) \).
  • The bottom of the lattice is the zero heuristic \( h = 0 \) — which reduces A* to UCS.
  • The top of the lattice is the exact heuristic \( h^* \).

Graph Search

Tree search does extra work: failure to detect repeated states can cause exponentially more work. In BFS, for example, we shouldn't bother expanding a node whose state we have already expanded.

Idea: Never expand a state twice.

Implementation:

  • Tree search + set of expanded states ("closed set").
  • Expand the search tree node-by-node, but before expanding a node, check to make sure its state has never been expanded before.
  • If not new, skip it. If new, add to closed set.
  • Important: store the closed set as a set, not a list.

Graph search does not wreck completeness — but it can wreck optimality if the heuristic is merely admissible rather than consistent.

A* Graph Search Gone Wrong

Consider a graph with \( S(h{=}2) \rightarrow A(h{=}4) \) and \( S \rightarrow B(h{=}1) \), both cost 1, with \( A \rightarrow C \) cost 1, \( B \rightarrow C \) cost 2, and \( C(h{=}1) \rightarrow G(h{=}0) \) cost 3.

  • Through B: \( C \) is reached with \( f = 3 + 1 = 4 \), and B looks cheaper first because \( h(B) \) is small.
  • Through A: \( C \) is reached with \( f = 2 + 1 = 3 \) — the genuinely cheaper path, cost 5 to the goal versus 6.
  • Because graph search closes \( C \) the first time it is expanded, the better path through A is discarded and A* returns the cost-6 plan.

The heuristic here is admissible but not consistent ( \( h(A) - h(C) = 3 > \text{cost}(A \rightarrow C) = 1 \) ), which is exactly what breaks it.

Optimality of A* Graph Search

Sketch — consider what A* does with a consistent heuristic:

  • Fact 1: In tree search, A* expands nodes in increasing total \( f \) value (f-contours).
  • Fact 2: For every state \( s \), nodes that reach \( s \) optimally are expanded before nodes that reach \( s \) suboptimally.
  • Result: A* graph search is optimal.

Summary

A* is optimal if… UCS is the special case…
Tree search the heuristic is admissible \( h = 0 \) is admissible
Graph search the heuristic is consistent \( h = 0 \) is consistent
  • Consistency implies admissibility (but not the other way round).
  • In general, most natural admissible heuristics tend to be consistent, especially if derived from relaxed problems.
  • A* uses both backward costs and (estimates of) forward costs.
  • A* is optimal with admissible / consistent heuristics.
  • Heuristic design is key: often use relaxed problems.
