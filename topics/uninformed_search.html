Uninformed Search Strategies

Class 3  •  AIMA 3.4

Search Problems

A search problem consists of:

  • A state space: The set of all possible states.
  • A successor function: Returns actions and costs.
  • A start state and a goal test.

A solution is a sequence of actions (a plan) which transforms the start state to a goal state.

Example: Traveling in Romania

  • State space: Cities.
  • Successor function: Roads — go to an adjacent city with cost = distance.
  • Start state: Arad.
  • Goal test: Is state == Bucharest?

What's in a State Space?

The world state includes every last detail of the environment. A search state keeps only the details needed for planning — this is abstraction. The same world can give very different search states depending on the problem:

Problem: Pathing Problem: Eat-All-Dots
States \((x, y)\) location \(\{(x,y),\ \text{dot booleans}\}\)
Actions NSEW NSEW
Successor Update location only Update location and possibly a dot boolean
Goal test Is \((x,y) = \text{END}\)? Dots all false

State Space Graphs vs. Search Trees

  • State Space Graph: A mathematical representation of a search problem. Nodes are abstracted world configurations. Arcs represent successors (action results). The goal test is a set of goal nodes (maybe only one). In a state space graph, each state occurs only once! We can rarely build this full graph in memory (it's too big), but it's a useful idea.
  • Search Tree: A "what if" tree of plans and their outcomes. The start state is the root node. Children correspond to successors. Nodes show states, but correspond to PLANS that achieve those states. For most problems we can never actually build the whole tree.

Each node in the search tree is an entire path in the state space graph. We construct both on demand — and we construct as little as possible.

Quiz: for a small 4-state graph (S, a, b, G) with cycles, the search tree is infinite. Important: there is lots of repeated structure in the search tree!

General Tree Search

Search means: expand out potential plans (tree nodes), maintain a fringe of partial plans under consideration, and try to expand as few tree nodes as possible.

function TREE-SEARCH(problem, strategy) returns a solution, or failure initialize the search tree using the initial state of problem loop do if there are no candidates for expansion then return failure choose a leaf node for expansion according to strategy if the node contains a goal state then return the corresponding solution else expand the node and add the resulting nodes to the search tree

The important ideas are:

  • Fringe: the set of nodes generated but not yet expanded.
  • Expansion: generating the successors of a node.
  • Exploration strategy: the rule that picks which fringe node to expand next.

The main question: which fringe node do we explore next? Every uninformed algorithm below is just a different answer to that one question — implemented by changing the data structure used for the fringe.

Search Algorithm Properties

We evaluate search algorithms based on the following properties:

  • Complete: Guaranteed to find a solution if one exists?
  • Optimal: Guaranteed to find the least cost path?
  • Time complexity: How long does it take?
  • Space complexity: How much memory is needed?

Cartoon of the search tree: \( b \) is the branching factor, \( m \) is the maximum depth, and solutions may sit at various depths.

Number of nodes in entire tree = \( 1 + b + b^2 + \dots + b^m = O(b^m) \)

Two more symbols used throughout: \( s \) (sometimes written \( d \)) is the depth of the shallowest solution, and \( \ell \) is a depth limit imposed by the algorithm.

Uninformed Search Algorithms

1. Depth-First Search (DFS)

Strategy: expand a deepest node first. Implementation: Fringe is a LIFO stack.

DFS expands some left prefix of the tree, and could process the whole tree.

  • Time Complexity: \( O(b^m) \) if \( m \) is finite.
  • Space Complexity: \( O(bm) \) — only has siblings on the path to root.
  • Complete? \( m \) could be infinite, so only if we prevent cycles.
  • Optimal? No, it finds the "leftmost" solution, regardless of depth or cost.

2. Breadth-First Search (BFS)

Strategy: expand the shallowest node first. Implementation: Fringe is a FIFO queue.

BFS processes all nodes above the shallowest solution. Let the depth of the shallowest solution be \( s \).

  • Time Complexity: \( O(b^s) \)
  • Space Complexity: \( O(b^s) \) — has roughly the last tier in the fringe.
  • Complete? Yes — \( s \) must be finite if a solution exists.
  • Optimal? Only if costs are all 1.

Quiz: DFS vs. BFS

When will BFS outperform DFS, and when will DFS outperform BFS?

Scenario BFS better? DFS better?
Finding shortest path✅ Yes❌ No
Shallow & wide search space✅ Yes❌ No
Deep & narrow search space❌ No✅ Yes
Memory-constrained environments❌ No✅ Yes
Finding any solution (not optimal)❌ No✅ Yes
Solution is close to root✅ Yes❌ No

3. Depth Limited Search (DLS)

Strategy: Use DFS with a depth limit \( \ell \). Nodes at depth \( \ell \) are treated as if they had no successors, so the search cannot run off down an infinite branch.

function DEPTH-LIMITED-SEARCH(problem, limit) returns a solution, or failure/cutoff return RECURSIVE-DLS(MAKE-NODE(problem.INITIAL-STATE), problem, limit) function RECURSIVE-DLS(node, problem, limit) returns a solution, or failure/cutoff if problem.GOAL-TEST(node.STATE) then return SOLUTION(node) else if limit = 0 then return cutoff else cutoff_occurred? <- false for each action in problem.ACTIONS(node.STATE) do child <- CHILD-NODE(problem, node, action) result <- RECURSIVE-DLS(child, problem, limit - 1) if result = cutoff then cutoff_occurred? <- true else if result != failure then return result if cutoff_occurred? then return cutoff else return failure

Properties of DLS:

  • Time Complexity: \( O(b^{\ell}) \)
  • Space Complexity: \( O(b\ell) \)
  • Complete? No — incomplete if the shallowest goal is deeper than the limit ( \( \ell < s \) ). It returns cutoff rather than a solution.
  • Optimal? No, for the same reason DFS isn't: it returns the leftmost solution within the limit.

The obvious difficulty is choosing \( \ell \). Pick it too small and you miss the goal; pick it too large and you pay DFS's worst-case cost.

4. Iterative Deepening Search (IDS / IDDFS)

Idea: get DFS's space advantage with BFS's time / shallow-solution advantages, without having to guess a good depth limit. Iterative deepening simply calls depth-limited search with a limit that grows by one each round:

  • Run a DFS with depth limit 1. If no solution…
  • Run a DFS with depth limit 2. If no solution…
  • Run a DFS with depth limit 3… and so on until a solution is found.
function ITERATIVE-DEEPENING-SEARCH(problem) returns a solution, or failure for depth = 0 to ∞ do result <- DEPTH-LIMITED-SEARCH(problem, depth) if result != cutoff then return result

Isn't that wastefully redundant? Generally most work happens in the lowest level searched, so it's not so bad. Nodes on the bottom level are generated once, those on the next level up twice, and so on up to the root which is generated \( s+1 \) times:

\[ N(\text{IDS}) = (s+1)b^0 + (s)b^1 + (s-1)b^2 + \dots + (1)b^{s} \]

For \( b = 10, s = 5 \): IDS generates 123,456 nodes versus 111,111 for BFS — about 11% overhead. The larger \( b \) gets, the smaller the overhead becomes.

Properties of Iterative Deepening:

  • Time Complexity: \( O(b^s) \) — the same order as BFS, because the last iteration dominates.
  • Space Complexity: \( O(bs) \) — the same as DFS, since only one path is ever in memory. This is the whole point of the algorithm.
  • Complete? Yes, when \( b \) is finite — the limit eventually reaches \( s \).
  • Optimal? Yes, if all step costs are identical (like BFS). Not optimal for general costs — use UCS for that.

Iterative deepening is the preferred uninformed method when the state space is large and the depth of the solution is not known: it combines the low memory of DFS with the completeness and shallow-solution guarantee of BFS.

5. Cost-Sensitive Search & Uniform Cost Search (UCS)

BFS finds the shortest path in terms of number of actions. It does not find the least-cost path when arcs have different costs. UCS is the algorithm that does.

Strategy: Expand the cheapest node first. Implementation: Fringe is a priority queue (priority = cumulative cost \( g(n) \)).

UCS processes all nodes with cost less than the cheapest solution. If that solution costs \( C^* \) and arcs cost at least \( \epsilon \), then the "effective depth" is roughly \( C^*/\epsilon \).

  • Time Complexity: \( O(b^{C^*/\epsilon}) \) — exponential in the effective depth.
  • Space Complexity: \( O(b^{C^*/\epsilon}) \) — has roughly the last tier.
  • Complete? Yes, assuming the best solution has a finite cost and the minimum arc cost is positive.
  • Optimal? Yes!

Uniform Cost Issues: UCS explores increasing cost contours in every "direction", because it has no information about where the goal is. The good: it is complete and optimal. The bad: it wastes effort exploring away from the goal — which is exactly what heuristics fix in Informed Search.

Summary: Comparing the Strategies

\( b \) = branching factor, \( m \) = max depth, \( s \) = depth of shallowest solution, \( \ell \) = depth limit, \( C^* \) = optimal cost, \( \epsilon \) = minimum arc cost.

DFS LIFO stack Only if cycles prevented No \( O(b^m) \) \( O(bm) \)
BFS FIFO queue Yes Only if costs all 1 \( O(b^s) \) \( O(b^s) \)
